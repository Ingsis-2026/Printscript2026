parser

Groups the token stream into statements and turns each statement into an AST node, lazily. It has two halves: a state machine that decides where a statement ends, and a chain of factories that each know how to build one kind of statement.

Say it like this

"The parser works in two steps. First, the StatementSplitter reads tokens and cuts them into statements: at a ;, or when a block closes. It counts braces so a whole if/else stays together. Then, for each statement, the parser asks a list of factories, in order, "can you handle this?", and the first one that says yes builds the node. The version decides which factories are in the list: 1.0 has no ConditionalFactory. Blocks are parsed recursively by a fresh sub-parser. Everything is a Sequence, so only the statement being built is ever held in memory."

Part 1 · Splitting statements

StatementSplitter is a state machine over the token stream. Its only job is to decide where a statement ends.

Every rule asks what role a token plays, not what its text is (TokenRoles.kt:12–24): opensBlock is a PUNCTUATOR {, startsConditional a CONDITIONAL if. The lexer strips a string literal's quotes, so the value of println("}")'s argument is }, exactly like a brace. Comparing text alone used to cut statements there; and under 1.0, where if is just a name, let if: number = 1; looked like a conditional.

Part 2 · Choosing a factory

For each statement, Parser uses the first factory whose canHandle returns true.

Shaded cells are the factory that actually builds the node. Each canHandle is a one-line check for the presence of a token (if, a leading println, a KEYWORD, a =, a FUNCTION), so several factories often say yes, and the list order breaks the tie:

  • Conditional first: an if statement contains declarations and assignments in its blocks.
  • Println before Function: println is itself a FUNCTION token.
  • Declaration before Assignation: let c: number = … contains a =.
  • Function last: a readInput call nested in a declaration or assignment must go to that factory. FunctionFactory only builds a call that stands alone.

The version is nothing more than which list you get. 1.0 is the same list without ConditionalFactory, so an if reaching the 1.0 parser has no factory to build it.

  • The type becomes a DataType (:24–26). The token's text is looked up once, and from then on the parser and the interpreter compare enum values, not strings.

  • Split at the = (:13–18): the left side is what comes before it, the right side what comes after.
  • The right side is an expression (:22), handed to ExpressionParser like every other. An empty one is NilNode.
  • The left side must be one name (:36–40). Several tokens before the = could only be a declaration, and without a keyword it isn't one. That's how 1.0 rejects const x: number = 1, where const is just an identifier (:39).
  • Position = the = token (:24). a = 5; gives Assignation a @0:2.

ExpressionParser

13internal object ExpressionParser {14    /** De la que liga menos a la que liga más: `a + b * c` se parte primero por el `+`. */15    private val PRECEDENCE_LEVELS = listOf(setOf("+", "-"), setOf("*", "/"))1617    fun parse(tokens: List<Token>): ASTNode =18        when {19            isEnclosedInParentheses(tokens) -> parse(tokens.subList(1, tokens.lastIndex))20            tokens.size == 1 -> tokens.single().toLiteral()21            tokens.any { it.namesFunction } -> call(tokens)22            else -> operation(tokens)23        }2425    private fun call(tokens: List<Token>): FunctionNode {26        val nameIndex = tokens.indexOfFirst { it.namesFunction }27        val name = tokens[nameIndex]28        val openingParenthesis = nameIndex + 129        val closingParenthesis = tokens.lastIndex30        val argument = tokens.subList(openingParenthesis + 1, closingParenthesis)31        if (argument.isEmpty()) throw ParserException("${name.value} needs an argument", tokens)32        return FunctionNode(33            type = name.getType(),34            functionName = name.value,35            expression = parse(argument),36            position = name.getPosition(),37        )38    }3940    private fun operation(tokens: List<Token>): ASTNode =41        PRECEDENCE_LEVELS.firstNotNullOfOrNull { operators -> splitAtFirst(tokens, operators) }42            ?: throw ParserException("Error in operation", tokens)4344    /** Parte por el primer operador de [operators] que no esté dentro de un paréntesis. */45    private fun splitAtFirst(46        tokens: List<Token>,47        operators: Set<String>,48    ): BinaryNode?   • One entry point that reads as the grammar (:17–23): an expression is another expression in parentheses, a single token (a literal), a call, or an operation. Every factory that has an expression calls parse, so there's one place to look.
  • Parentheses that wrap everything are dropped, however many there are (:19, :66–75). (2 + 3) loses them. (2 + 3) * (4 + 5) keeps them, because the depth returns to 0 before the end.
  • A call's argument sits between the ( after the name and the final ) (:28–30), and is itself an expression (:35). An empty argument is an error at the call (:31).
  • Precedence is data (:15): split at a + or - first; only if there is none, split at * or / (:40–42). The operator you split at becomes the root, so it's evaluated last, which is exactly lower precedence.
  • Parentheses shield operators (:49–53): depth counts them, and only operators at depth 0 are split points. Both halves go back through parse (:55–56).
  • Parentheses and operators are recognised by type (:51–53, :67), so a string "(" or "+" is an operand. Comparing text alone made println("a" + "+" + "b"); split at the middle string and crash on an empty operand.

Decisions to defend

Each with the cost we accepted.

Two parts, a splitter and builders, instead of one recursive-descent parser

The statement is the natural unit for streaming, and the splitter is the only place that holds tokens. Factories only ever see a complete statement, so each one is simple and has a single job.

CostThe splitter needs a little grammar knowledge of its own (braces, if, else) that a single grammar would keep in one place.

An ordered chain of responsibility

A new construct is a new factory added to a list, and Parser doesn't change (Open/Closed). The language version is the list itself (ParserFactory.kt:13–17).

CostcanHandle checks are coarse, so the list order carries meaning, as the matrix shows. Reordering the list changes behaviour.

Hold a closed block for one token, to attach else

if { } else { } is one statement, and it becomes one ConditionalNode. Looking one token ahead is the minimum needed to know.

CostAn if without else isn't emitted until the next token arrives. The measurement shows this: 7 lines read for a statement ending on line 6.

Blocks parsed by a sub-parser created through a lambda

Recursion comes for free, since blocks inside blocks follow the same rules. The lambda (ConditionalFactory.kt:20) delays building the sub-parser until a block actually appears. Building it eagerly would loop forever: Parser.forVersion(Version.V1_1) creates a ConditionalFactory, which would create another parser for 1.1, and so on. Tests can also pass in a fake parser.

CostA whole if statement is held in memory while it's parsed. Blocks are small compared with files, so streaming still holds at file scale.

One expression parser for every statement

Declarations, assignments, println and call arguments all hand their expression to ExpressionParser.parse (ExpressionParser.kt:17–23). "Where are expressions parsed?" has one answer, and the four cases of the when are the grammar. It's also why println(readInput("n?")) works: println uses the same parser as a declaration.

CostA FUNCTION token anywhere makes the expression a call (:21), so readInput("a") + 1 isn't read as an operation. The factories had the same limit; now it's in one place.

Precedence by splitting at the lowest-precedence operator

Four operators and parentheses fit in about 60 lines, and a new precedence level is one more set in PRECEDENCE_LEVELS (ExpressionParser.kt:15).

CostWith many operators or levels, a precedence-climbing (Pratt) parser would scale better. PrintScript isn't there.

A literal-only type check at parse time

An obvious let x: number = "hi" fails during validation, before anything runs, and the error points at the expression.

CostIdentifiers and readInput can't be checked without a symbol table, so those checks happen at run time in the interpreter.

Structure is recognised by token type, in one place

Whether a token opens a block, ends a statement, starts an if or is an operator is answered by TokenRoles.kt, which checks the type as well as the text. The splitter and the factories all ask the same questions the same way, so a string that happens to read }, ;, ( or + stays a string.

CostTests that build tokens by hand must use the types the lexer really produces. Several used to label ( or = as PUNCTUATOR and had to be corrected.

One splitter with an insideBlock flag

The top level and block bodies follow the same rules except for one: whether a } ends the last statement or is an error (StatementSplitter.kt:51–59). One flag avoids maintaining two nearly identical state machines.

CostA boolean argument changes behaviour, so the call site has to name it (insideBlock = true, Parser.kt:38) to stay readable.

Questions you might get

Short answers, with the line to show.

Why not ANTLR or a classic recursive-descent parser?

Streaming by statement fell out of this design naturally, each construct is isolated in its own factory, and versions are two lists. ANTLR adds a grammar file, a generator step and generated code, and two versions would mean two grammars or grammar-level flags.

Why is ConditionalFactory first in the list?

An if statement contains a KEYWORD and a = inside its blocks, so DeclarationFactory and AssignationFactory would also claim it. The matrix above shows three factories answering yes.

How does an else end up on the right if?

readElseBlock only looks at the token immediately after the then-block's matching } (ConditionalFactory.kt:85). An else inside a nested block is inside that block's braces, so the outer if never sees it. The test is "an else belongs to its own if and not to the enclosing one".

Why can the last statement in a block skip its ;?

The block body is passed to the sub-parser with its closing } (ConditionalFactory.kt:70), and in insideBlock mode that } ends the pending statement (StatementSplitter.kt:51–57).

Doesn't holding a whole if break streaming?

Streaming is about the file: the parser never holds more than the current statement. A block is part of one statement. The TCK's 131,072-statement test and StreamingPipelineTest ("taking a few statements reads only a few lines") cover this.

Where is an if rejected in 1.0?

In practice, the lexer fails first on {, a symbol 1.0 doesn't have. Before that, if is already just an identifier under 1.0, so nothing treats it as a conditional; and even so, the 1.0 factory list has no ConditionalFactory. The test is "parser version 1_0 does not support conditionals".

What does the parser do with println("}");?

Nothing special. The lexer hands over a STRINGLITERAL whose value is }, and the splitter asks closesBlock, which requires a PUNCTUATOR (TokenRoles.kt:14). The test is "a string that reads like a brace or a semicolon does not cut the statement".

Why do factories find tokens by type instead of by fixed index?

It's forgiving about shape, so each factory stays short, and the specific "Expected a … token" messages come from the same find calls. The splitter has already guaranteed that the factory is looking at exactly one statement.
