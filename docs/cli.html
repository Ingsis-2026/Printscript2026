Say it like this

"The CLI is ./printscript <operation> <file> with optional --version, --config and --output. An ArgumentParser validates everything it can before touching the source. A CommandFactory builds one of four commands with its collaborators already wired, and the command runs. There's exactly one place that catches errors, and it maps outcomes to exit codes: 0 success, 1 a problem in the source, 2 a problem with how the tool was invoked or configured. Results go to stdout and everything else, including progress, goes to stderr, so formatted code can be redirected to a file. Progress is shown statement by statement while parsing, as the assignment requires."

Demo runbook

Every command below was run against the built CLI. The output shown is what appeared in a real terminal, and the chip is the exit code.

0

The operation succeeded. For analyzing: no violations.

1

A problem in the source (lexical, syntax, run time), violations found, or an I/O error.

2

A problem in the invocation or the configuration file. Usage errors also print the usage line.

Check the exit code after any command with echo $?.

0 · Before you start

Run once, from the repository root.

Build the CLI

installDist produces cli/build/install/printscript/bin/printscript. The ./printscript wrapper in the repository root runs it, and builds it first if it isn't there yet, so this step is optional.

./gradlew :cli:installDist

Every command below uses ./printscript from the repository root. After changing the code, run ./gradlew :cli:installDist again so the wrapper picks up the new build. Prefer typing printscript with no ./? Add the bin directory to your PATH in ~/.zshrc: export PATH="$PATH:/ruta/al/repo/cli/build/install/printscript/bin".

Create the demo files

Seven small files in /tmp/ps-demo: a readInput program, a readEnv program, badly spaced code, a 1.1 block, two formatter configs, and a 200,000-line file. It all runs in a subshell, so your own shell stays in the repository root.

( mkdir -p /tmp/ps-demo && cd /tmp/ps-demo || exit 1 printf 'let name: string = readInput("Name?");\nprintln("Hi " + name);\n' > greet.ps printf 'let who: string = readEnv("DEMO_NAME");\nprintln("Hello " + who);\n' > env.ps printf 'let total:number=10;let label :string="Total: ";\nprintln(label+total);\n' > messy.ps printf 'const ok: boolean = true;\nif(ok)\n{\nprintln("inside");\n} else {\n println("never");\n}\n' > block.ps printf 'enforce-spacing-after-colon-in-declaration: true\nenforce-spacing-around-equals: true\nmandatory-space-surrounding-operations: true\nmandatory-line-break-after-statement: true\n' > rules.yaml printf '{\n "if-brace-same-line": true,\n "indent-inside-if": 4\n}\n' > rules11.json yes 'println("x");' | head -n 200000 > big.ps )

If a command says El archivo fuente no existe, you're probably in another directory. The commands that use cli/src/test/resources/… are relative to the repository root; the /tmp/ps-demo/… ones work from anywhere. cd back to the repo and try again.

Needs --config (YAML or JSON). The formatted code goes to stdout or to --output.

The shared parsing pipeline and progress

27class ParsingPipeline(28    private val version: Version,29    private val progressReporter: ProgressReporter = NoOpProgressReporter,30) {31    fun <T> consume(32        source: Source,33        block: (Sequence<ASTNode>) -> T,34    ): PipelineResult<T> {35        var parsed = 036        val value =37            source.useLines { lines ->38                val nodes =39                    nodesFrom(lines).onEach {40                        parsed += 141                        progressReporter.onStatementParsed(parsed)42                    }43                block(nodes)44            }45        progressReporter.onFinished(parsed)46        return PipelineResult(value, parsed)47    }4849    private fun nodesFrom(lines: Sequence<String>): Sequence<ASTNode> {50        val tokens = Lexer(TokenMapper(version)).convertToTokens(lines)51        return Parser.forVersion(version).execute(tokens)52    }53}
  • Shared by three commands: validation, execution and analyzing all need lexer plus parser for the chosen version (:49–52).
  • Progress without knowing the total (:39–42): onEach counts statements as the consumer pulls them. The count is reported while parsing, not after, as the assignment asks.
  • useLines keeps the file open only for the block (:37): the whole consumption happens inside it.

  • Source only offers useLines (Source.kt:14), with no "read everything", so no command can accidentally load a whole file.
  • One reader on stdin (ConsoleReader.kt:13). Creating a new reader per readInput would discard what the previous one had buffered, and piped input would lose lines.
  • OutputPrinter adapts the interpreter's Printer to the result channel; FileSink writes formatted lines to a file.

Decisions to defend

Each with the cost we accepted.

Command + factory + invoker instead of a big when in main

Each operation is a small class that receives ready-made collaborators. A fifth operation is an enum entry, a command and a factory branch.

CostMore files (27) than a single-file CLI. Each is small and tested in isolation.

One error boundary, with three exit codes

Every operation reports errors identically, with the position from describe(). Codes separate "your program has a problem" (1) from "you invoked me wrong" (2), which scripts can act on.

CostThe mapping depends on exception types, so a new kind of failure needs a deliberate choice of code.

Validate arguments before opening the source

A missing config, a wrong version or a missing file fails immediately with the usage line, and commands never check arguments again.

CostSome validation needs the file's contents, such as which linter rules the version allows. That arrives later, as a configuration error.

stdout is only the result

formatting … > out.ps produces a clean file, and a program's output can be piped. Progress and messages never pollute the result.

CostIn a terminal both streams share the screen, so program output can appear right after the progress text on one line. 2>/dev/null shows only the result.

Progress by statements, on one line

Parsing is lazy, so the total isn't known in advance. Counting statements as they're parsed is the honest measure, and \r keeps it to one line.

CostNo percentage or time estimate, just a running count.

Source, Output and ProgressReporter as interfaces

Tests run every command against in-memory doubles (TestDoubles.kt), and Source's shape enforces streaming.

CostAn extra layer of small classes between the commands and the console.

Questions you might get

Short answers, with the line to show.

Show me the CLI validating a file, running it, and failing.

Use the 5-minute order above: validation of example2.ps, execution with 2>/dev/null, test19.txt with and without --version 1.1, then invalidCharacter.ps. Finish with echo $? to show the exit codes.

How do exit codes 1 and 2 differ?

1 means something is wrong with the source: a lexical, syntax or run-time error, violations, or I/O. 2 means something is wrong with the invocation or configuration: missing arguments, unknown options, an unsupported version, bad rules. It's decided in PrintScriptCli.kt:26–48.

Where is the progress the assignment asks for?

ParsingPipeline.kt:39–42 calls the reporter for every statement as it's parsed, and ConsoleProgressReporter.kt:15 redraws the line on stderr. The 200,000-statement demo shows it counting.

How does readInput read from the console?

CommandFactory gives the interpreter a ConsoleReader with one BufferedReader on stdin, which reads a line per call. The prompt goes through the same printer as println.

Why doesn't validation need the interpreter?

Lexer and parser errors are thrown while nodes are pulled, so consuming all the nodes is enough (ValidationCommand.kt:19). Nothing runs and nothing is written to stdout.

How would you add an operation, say one that prints tokens?

Add TOKENS("tokens", requiresConfig = false) to Operation, write a TokensCommand, and add a branch to CommandFactory.create. The argument parser, error handling and exit codes already work.

Why is the analyzing report on stderr?

Violations are diagnostics about the source, like errors, not a product of the operation. The exit code carries the pass/fail result for scripts.
