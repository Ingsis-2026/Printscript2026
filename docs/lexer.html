lexer

Turns source text into a lazy stream of tokens, one line at a time. Each version is a plain list of words and symbols, so extending the language never means writing a regex, and anything that isn't in the vocabulary becomes an error at its exact column.

Say it like this

"Each version is a vocabulary: a map of its words and a map of its symbols, each with the token type it produces. The lexer reads the source one line at a time, left to right, and the first character decides what to read. A letter starts a name: we read the whole name, and it's a word if the version has it, or an identifier if it doesn't. A digit starts a number, a quote starts a string, and anything else has to be the longest symbol of the version that starts there. If nothing fits, it's an invalid character, reported at its column. There's no regex, so adding a word or a symbol to the language is one entry in a map. Because the output is a Sequence, a line is read only when the parser asks for more tokens, so memory depends on the longest line, not on the file size."

Where it sits

Three callers in production code, each feeding it lines lazily. The list-returning execute is used only by tests.

All three build the lexer the same way, Lexer(TokenMapper(version)). The lexer never learns who consumes its tokens, and the parser never imports the lexer; the callers above connect the two. That's why the lexer depends only on commons.

The vocabulary

  • A word is a name the version gives a type (:44–47). Adding while is one line: "while" to TokenType.CONDITIONAL.
  • A symbol is literal text (:51–61). Adding <= is one line too; there's nothing to escape and no position in a list to choose.
  • 1.1 is 1.0 plus what it adds (:65–84): eight words and the braces. Nothing is replaced, so the difference between the versions is exactly what's written.
  • Operators are only the ones the language has. % or ! aren't in any version, so they're invalid characters in the lexer, not errors discovered later.

Reading each kind of token

Four small readers, one per first character.

Names

43    /** Un nombre es una palabra de la versión si la versión la tiene, y un identificador si no. */44    private fun nameAt(start: Int): Token {45        val end = endOfRun(start) { it.continuesName() }46        val name = line.substring(start, end)47        return token(vocabulary.words[name] ?: TokenType.IDENTIFIER, name, start, end)48    }

The whole name is read before anything is decided (:45), and only then looked up in the version's words (:47). That's why letter is one identifier and not let + ter, and why printlnCount is a name. A name the version doesn't have is an identifier: under 1.0, const and if are just names.

Numbers

50    private fun numberAt(start: Int): Token {51        val integerEnd = endOfRun(start) { it.isNumeral() }52        val hasDecimals = line.getOrNull(integerEnd) == '.' && line.getOrNull(integerEnd + 1)?.isNumeral() == true53        val end = if (hasDecimals) endOfRun(integerEnd + 1) { it.isNumeral() } else integerEnd5455        if (line.getOrNull(end)?.continuesName() == true) {56            val runEnd = endOfRun(end) { it.continuesName() }57            throw LexerException("Número inválido: '${line.substring(start, runEnd)}'", position(start), position(runEnd))58        }59        return token(TokenType.NUMBERLITERAL, line.substring(start, end), start, end)60    }

Digits, then an optional . and more digits (:52). A . without a digit after it isn't part of the number, and since . isn't a symbol either, 3. is an error. A number glued to a name, like 123abc, is rejected on the spot (:55–58) instead of being quietly split into two tokens.

Strings

62    /** El valor de un string no lleva las comillas; su posición, sí. */63    private fun stringAt(start: Int): Token {64        val closing = line.indexOf(line[start], startIndex = start + 1)65        if (closing < 0) {66            throw LexerException("String sin cerrar: falta la comilla de cierre", position(start), position(line.length))67        }68        return token(TokenType.STRINGLITERAL, line.substring(start + 1, closing), start, closing + 1)69    }

A string ends at the next quote of the same kind (:64), so "it's" works. Without a closing quote it fails from the opening one to the end of the line (:65–66). The value drops the quotes, but the positions still cover them (:68), which is how the formatter recovers the original text.

The vocabulary answers "which symbol starts here?" by trying the longest ones first (TokenMapper.kt:22). Today every symbol is one character, so it doesn't matter yet. It's what lets a future <= win over < without anyone thinking about order. If no symbol starts at that column, the character is invalid (LineScanner.kt:74).

Nothing in the lexer rejects a word for belonging to another version. A 1.1 word just isn't in 1.0's map (TokenMapper.kt:42–48), so 1.0 reads it as a name, and the program fails where the grammar stops making sense. The lexer itself only stops {, a symbol 1.0 doesn't have.

12class Lexer(13    private val tokenMapper: TokenMapper,14) {15    fun execute(input: String): List<Token> = convertToTokens(input.lineSequence()).toList()1617    fun convertToTokens(lines: Sequence<String>): Sequence<Token> =18        lines.mapIndexed { row, line -> LineScanner(tokenMapper, row, line).tokens() }.flatten()1920    fun convertToTokens(inputStream: InputStream): Sequence<Token> =21        convertToTokens(BufferedReader(InputStreamReader(inputStream)).lineSequence())22}
  • lines.mapIndexed { … }.flatten() (:17–18). Sequence operations are lazy, so a line is scanned only when the consumer asks past the previous line's tokens. That's the first experiment: an infinite input can't hang it. mapIndexed supplies the row number.
  • The unit of work is a line. LineScanner.tokens() returns a complete List, and flatten hands it out token by token. That's the second experiment: a bad character anywhere in a line fails before that line's tokens are delivered. Memory is bounded by the longest line.
  • The InputStream overload (:20–21) wraps a BufferedReader and reuses the same path. The caller owns the stream and closes it.

Decisions to defend

Each with the cost we accepted.

A hand-written scanner over the version's vocabulary, not regex

Extending the language means adding an entry to a map (TokenMapper.kt:40–84), with no regex to write and no order to respect. The scanner reads what's in front of it and decides by the first character (LineScanner.kt:33–41). An earlier version of this lexer joined one regex per token type into a single pattern, and it needed two ordering rules, a check for skipped text and named groups to work.

CostAbout 100 lines of scanning code to explain, all in LineScanner.kt. A new kind of token, such as a comment, would need its own reader; new words and symbols don't.

The version decides the vocabulary; the lexer makes no rulings

There's no list of words "not allowed in this version". A version is its maps (TokenMapper.kt:34–38), and a word it doesn't have isn't in them. The words map isn't a reserved-word table that overrides the version: it is the version.

Costconst under 1.0 gets the parser's generic Expected a KEYWORD token instead of a tailored message. It's accurate and still positioned at column 1.

The longest symbol wins

Symbols are tried longest first (TokenMapper.kt:22), which replaces "put this pattern before that one" with a rule nobody has to maintain.

CostNothing today, since every symbol is one character. It's there so the first two-character operator doesn't bring an ordering problem back.

Errors are found where they happen

An invalid character, an unclosed string and a number glued to a name are each reported at their own columns (LineScanner.kt:57, 66, 74). The regex version had to infer invalid text from the gaps it skipped, so every problem came out as "invalid character".

CostThree error messages to keep consistent instead of one.

Lazy and line-granular

This meets the assignment's "sources that don't fit in memory" requirement. Memory is bounded by the longest line, rows come free from the line count, and the TCK's 131,072-line test passes in a 7 MB heap.

CostA token can't span lines, which is fine because PrintScript has no multi-line strings. An error later in a line surfaces before that line's earlier tokens are delivered.

Questions you might get

Short answers, with the line to show.

Why not regex, or a generator like JFlex?

Both make the vocabulary something you have to know a notation to change. Here a version is two maps (TokenMapper.kt:40–84), and the scanner that reads them is a few small functions. A generator would also add a grammar file, a build step and generated code, and versioning would mean two grammars.

How do you add while for 1.2?

Write VERSION_1_2 = VERSION_1_1 + TokenMapper(words = mapOf("while" to …), symbols = emptyMap()) and give it a branch in vocabularyOf (TokenMapper.kt:34–38). The compiler asks for that branch as soon as V1_2 is added to Version, because the when has no else. Lexer and LineScanner don't change.

How does it know let is a keyword and letter isn't?

It reads the whole name first (LineScanner.kt:45) and only then looks it up (:47). letter isn't in the words, so it's an identifier.

Why doesn't the lexer reject const in 1.0?

Because 1.0 doesn't have it. Which words exist is the version's decision, expressed as its map (TokenMapper.kt:42–48). Under 1.0 const is a name, and the parser rejects the statement.

Is if a valid variable name in 1.0?

Yes. The lexer reads it as an IDENTIFIER, and the parser decides what starts a conditional by token type, not by text (TokenRoles.kt:22), so let if: number = 1; is an ordinary declaration under 1.0.

Why does a string's value lose its quotes?

Everything downstream wants the content: the interpreter prints it, and the parser checks its type. The positions still cover the quotes (LineScanner.kt:68), and the formatter re-reads the original text when it needs them (SourceToken.kt:51).

Is the lexer thread-safe?

A Lexer holds only its vocabulary, which is immutable. Each line gets its own LineScanner (Lexer.kt:18), so one instance can serve several sources. Each returned sequence has its own state and should be consumed by one thread.

What does execute(input) do?

It splits a whole string into lines and returns the tokens as a list (Lexer.kt:15). Tests use it for convenience; production code always uses the Sequence or InputStream overloads.
